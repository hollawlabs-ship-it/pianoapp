# 피아노 연습 앱 · v6.1.0 (베타)

**템포가 아니라 표현을 중심에 둔** 연습 기록기입니다.

어쿠스틱 그랜드로 연습하므로 MIDI가 없습니다. 그래서 이 앱의 관측 채널은
마이크 녹음 하나뿐이고, 거기서 뽑아낸 **음량(RMS) 곡선**이 표현을 읽는 유일한 증거입니다.
앱 자체는 학습하지 않습니다. 쌓인 기록이 AI 코칭의 재료가 될 뿐입니다.

빌드 도구도, 서버도, 계정도 없습니다. 정적 파일 몇 개가 전부입니다.

## 써 보기

**웹 (베타)** — 배포 후 아래 주소로 접속합니다. 설치할 것이 없습니다.

```
https://<GitHub-아이디>.github.io/pianoapp/
```

홈 화면에 추가하면 앱처럼 전체 화면으로 열리고, 오프라인에서도 동작합니다.
(피아노 앞에서 인터넷이 끊겨도 구간·별점·녹음·메트로놈은 그대로 돌아갑니다.)

**로컬** — 마이크 녹음(`getUserMedia`)은 `https` 또는 `http://localhost`에서만 허용됩니다.
`index.html`을 파일로 직접 열면 녹음이 동작하지 않습니다.

```bash
powershell -ExecutionPolicy Bypass -File serve.ps1
```

브라우저가 자동으로 열립니다. 포트를 바꾸려면 `-Port 8200`.
Node나 Python 없이 Windows에 기본 포함된 PowerShell만으로 돕니다.

## 화면 — 건반 테마 (검정 + 흰색)

색상(hue)을 쓰지 않고 명도만으로 구성했습니다. 흰건반 위의 검은건반입니다.

색이 없으면 "빨강=나쁨, 초록=좋음" 같은 신호를 쓸 수 없으므로, 뜻은 다른 채널로 옮겼습니다.

| 신호 | 표현 |
|---|---|
| 문제 · 미해소 | 검정 채움 배지 (가장 시끄럽게) |
| 오늘 할 것 | 검정 테두리 배지 |
| 끝난 것 · 향상 | 옅은 회색 배지 (조용하게) |
| 상승 / 하락 | 값에 붙은 `+` `−` 부호 + 글자 굵기 |
| 이전 녹음 / 이번 녹음 | 회색 **파선** / 검정 **실선** |
| 구간별 향상 / 하락 곡선 | 실선 / **파선** |
| 목표선 · 기준선 | 파선 |
| 녹음 입력 과다(클리핑) | 빨간 막대 대신 **문장으로 경고** |

표현 5차원은 검정에서 회색으로 내려가는 명도 사다리로 구분하되, 막대마다 이름과
점수를 항상 함께 적어 색만으로 뜻을 전달하지 않습니다.

본문·보조 텍스트의 명도 대비는 WCAG 기준(각각 4.5:1, 3:1)을 모두 통과합니다.

## 표현 5차원

`다이내믹 · 레가토 · 프레이징 · 페달링 · 음색·터치`

구간마다 5차원을 따로 매깁니다. **하루에 한 차원씩만** 다루도록 설계했습니다 —
오늘의 처방도, 레슨 스케줄도 하루에 두 차원을 섞지 않습니다.

## 완성도 지수 (100점)

```
템포 30  +  표현 30  +  녹음검증 20  +  지적해소 20
```

- **템포 30** — 목표 대비 현재 템포. 목표의 50% 이하는 0점.
- **표현 30** — 전 구간 × 5차원 별점 평균.
- **녹음검증 20** — 최근 14일 안에 녹음으로 확인된 구간의 비율. 별점만 올리고 소리로 확인하지 않으면 오르지 않습니다.
- **지적해소 20** — 레슨 지적 중 해소된 비율.

지적해소 항목에는 두 가지 장치가 있습니다.

1. **유예 2일** — 어제 들은 말을 오늘 못 고친 건 정상입니다. 방금 받은 지적 때문에 완성도가 떨어지지 않습니다.
2. **측정 불가 처리** — 레슨 기록이 없는 곡은 "지적 0건"으로 공짜 20점을 받지 않습니다. 이 항목을 빼고 나머지 80점을 100점으로 환산합니다. (그렇지 않으면 손도 안 댄 곡이 열심히 한 곡보다 높게 나옵니다.)

## 정체 감지

세 갈래로 봅니다.

- **전체** — 12일간 완성도가 3점 미만으로 움직였는데 연습 시간은 3시간을 넘겼다 → 시간이 아니라 방법의 문제
- **구간** — 평균 3.2점 이하이면서 별점이 12일 넘게 그대로
- **지적** — 레슨을 두 번 더 받도록 미해소이거나 14일 경과

## 음량 곡선을 읽는 법

녹음에서 뽑는 지표는 네 가지입니다.

| 지표 | 뜻 |
|---|---|
| **다이내믹 폭** | 셈여림의 층이 얼마나 넓은가 (0~1) |
| **곡선 일관성** | 정점이 하나로 모이는가, 여러 번 오르내리는가 |
| **정점 위치** | 클라이맥스가 곡의 몇 % 지점에 있는가 |
| **방향 전환** | 오르내림이 몇 번인가 |

두 녹음을 고르면 곡선을 겹쳐 A/B로 비교합니다. 판정에는 함정이 하나 있어서
따로 처리했습니다 — **평평하던 연주에 굴곡을 넣으면 "일관성" 수치는 반드시 떨어집니다.**
그걸 후퇴로 읽지 않도록, 다이내믹 폭의 변화를 먼저 보고 일관성은 그 안에서 해석합니다.

### API 키를 다루는 방식

이 앱에는 서버가 없어서 브라우저가 Anthropic API를 직접 호출합니다. 그래서 키는
**입력한 브라우저 밖으로 나가지 않습니다** — 저희 서버로 전송되지 않고, 내보내기 JSON에도 담기지 않습니다.

저장 위치는 두 가지 중에 고를 수 있습니다.

| | 저장 위치 | 수명 | 쓸 상황 |
|---|---|---|---|
| **기본** | `sessionStorage` | 탭을 닫으면 삭제 | 공용·공유 기기, 처음 써 보는 경우 |
| 설정에서 켬 | `localStorage` | 지울 때까지 유지 | 본인 개인 기기 |

> ⚠️ **'이 기기에 키 기억하기'를 켜면 키가 그 브라우저에 평문으로 남습니다.**
> 개인 기기에서만 켜세요. 공용 PC라면 기본값(세션 한정) 그대로 두면 됩니다.
> 어느 쪽이든 설정의 **키 지우기**로 즉시 삭제할 수 있습니다.

키가 걱정되거나 없어도 괜찮습니다. 규칙 기반 분석은 키 없이 전부 동작합니다.

## 배포

`main`에 푸시하면 GitHub Actions가 GitHub Pages로 그대로 올립니다. 빌드 단계는 없습니다.

최초 1회만 저장소 설정이 필요합니다: **Settings → Pages → Source → GitHub Actions**.

워크플로는 배포 전에 `index.html` · `manifest.json` · `sw.js` · `.nojekyll`이 있는지,
그리고 **`js/core/util.js`의 `PA.VERSION`과 `sw.js`의 `VERSION`이 일치하는지** 확인합니다.
둘이 어긋나면 서비스 워커가 낡은 자산을 계속 내보내므로, 자산을 고쳤다면 **두 곳의 버전을 함께 올려야 합니다.**

## 알려진 제약

- **영상 업로드**는 브라우저가 컨테이너를 오프라인 디코딩하지 못하면 실시간으로 훑습니다 — 영상 길이만큼 시간이 걸립니다.
- **녹음 시 자동 음량 보정을 끕니다.** 이걸 켜 두면 다이내믹이 뭉개져 분석이 무의미해집니다. 대신 녹음이 다소 작게 들릴 수 있습니다.
- **드롭박스 연동은 아직 없습니다.** ID/PW 방식은 보안상 쓰지 않기로 했고, 앱 폴더 토큰 방식으로 예정되어 있습니다.
- 롤모델 검색 결과의 유튜브 링크는 AI가 웹에서 찾은 것입니다. **열어서 실제로 맞는 연주인지 확인하세요.**
